# 常见问题 FAQ · Polymarket BTC 5m 与 OKX BTC 合约自动化

[← 项目首页](../../README.md) · [文档中心](./README.md) · [English](../en/faq.md)

这里直接回答首次了解、安装、运行和评估本软件时最常见的问题。涉及实际操作时，以对应版本的 [快速开始](./quick-start.md)、[安装与部署](./deployment.md) 和 Release 说明为准。

> **阅读前说明：** 历史回放、资金模型和模拟运行不是已实现的实盘收益，不保证未来表现；本软件不是 Polymarket 或 OKX 官方产品，不用于规避平台地区限制。本文不披露专有策略规则或内部参数。

## 1. 产品是什么，是否适合我？

<a id="q01"></a>

### Q1. 这是什么软件？支持哪些市场？

这是供用户在自己电脑或服务器上运行的自动交易系统。现有公开文档主要覆盖 **Polymarket BTC 5 分钟 Up / Down** 和 **OKX `BTC-USDT-SWAP` 永续合约**；两者有独立的信号与交易执行链路，不应将其理解为同一策略在不同交易所复制下单。[了解公开架构](./architecture.md)

<a id="q02"></a>

### Q2. 有 Windows 版本吗？可以部署在 Linux/VPS 上吗？

有。公开安装方式包括 **Windows 10/11（64 位）安装包**以及 **Linux x86_64 / VPS 云端部署**（推荐 Ubuntu LTS）。Linux 运行还需要具备 SSH、服务器权限及访问相关服务的网络条件。[查看安装与部署](./deployment.md)

<a id="q03"></a>

### Q3. 不会写代码，也能使用吗？

Windows 用户无需自行编译源码，可以下载安装包并通过界面配置。Linux 也提供命令部署方式，但需要基本的 SSH、服务器和网络管理能力。**安装完成不等于已激活、配置完成或可以安全启用实盘。** [查看快速开始](./quick-start.md)

<a id="q04"></a>

### Q4. 这是 Polymarket 或 OKX 的官方机器人吗？

不是。本软件为独立研发项目，与 Polymarket 和 OKX 均无官方隶属或背书关系。平台的交易规则、服务范围和账户限制仍以各自官方说明为准。

<a id="q05"></a>

### Q5. GitHub 仓库是否开源了完整策略和软件？

没有。仓库主要提供公开说明、研究报告、安装与迁移脚本，以及发行安装包的下载入口；**完整专有策略源码没有公开**。公开可读、可以下载安装不等于取得开源许可。[查看许可说明](../../LICENSE)

<a id="q06"></a>

### Q6. 软件是完全免费的吗？下载后就能交易吗？

软件需要设备激活授权，可申请 7 天体验或购买按期限计费的正式授权。具体价格、使用条件及免责声明见 [软件授权说明](./licensing.md)；首次使用步骤见 [快速开始](./quick-start.md)。

## 2. 下载、激活、部署与更新

<a id="q07"></a>

### Q7. 从哪里下载，安装后怎么开始？

从 [GitHub Releases](https://github.com/naka2027/polymarket-bot/releases/latest) 获取正式版本，按操作系统完成安装。首次启动后按提示获取设备机器码，通过官方支持渠道申请激活，完成基础设置，然后先在 **Paper（模拟）模式**检查数据、信号、订单状态和日志。[查看逐步指南](./quick-start.md)

<a id="q08"></a>

### Q8. Linux 的“一键部署”是否等于已经能自动交易？

不是。一键部署解决的是软件包获取、校验、安装和服务启动；后续仍需要管理员初始化（如适用）、激活授权、配置、必要的策略状态准备及模拟验证。不要将“服务运行正常”理解为“已经准备好实盘下单”。[查看云端部署](./deployment.md)

<a id="q09"></a>

### Q9. 为什么 Linux 控制台不能直接用服务器公网 IP 的 8765 端口访问？

公开部署文档中的默认控制台监听地址是 `127.0.0.1:8765`，仅允许服务器本机访问。可以先通过 **SSH 隧道**访问；若需要域名访问，应根据文档配置反向代理和 HTTPS，而不是直接把本地监听服务暴露到公网。[查看域名、Nginx 与宝塔设置](./deployment.md#4-域名与反向代理访问控制台)

<a id="q10"></a>

### Q10. 更新软件会不会清空配置、日志和长期状态？

更新与迁移有专门流程，但不能在未检查安装版本、部署方式及迁移条件时保证“绝不会丢失数据”。更新前请先查看 Release 说明，检查未完成订单及仓位，按需要做好备份；更新后确认版本、配置、订单状态和策略准备状态。[查看更新与迁移](./deployment.md#5-云端更新与旧版迁移)

## 3. Paper、Live 与实际执行

<a id="q11"></a>

### Q11. Paper 模拟模式和 Live 实盘模式有什么区别？

Paper 用于观察和验证运行流程及模拟结果，不等同于真实成交；Live 涉及真实账户、真实订单、成交价格、费用、滑点与资金风险。**Paper 的盈亏记录不能作为实盘收益证明。** 首次使用建议先完成模拟验证。[查看首次使用](./quick-start.md)

<a id="q12"></a>

### Q12. 为什么初次启动后某些策略显示“准备中”？“停止”一定是错误吗？

部分策略需要检查并补齐历史数据、按时间顺序准备依赖状态。在必需状态仍显示“准备中”或“异常”时，不应贸然启动自动化；但个别影子显示“停止”可能是有效的控制状态，并不要求全部变成“启动”。[查看状态准备说明](./quick-start.md#影子首次准备)

<a id="q13"></a>

### Q13. 为什么机器人运行着，却没有下单？

不一定是故障：当前窗口可能没有有效候选，策略主动跳过，必需状态尚未就绪，仓位或账户风控阻止下单，或市场数据、订单接口存在异常。应结合**当前状态、订单历史和日志**判断原因，而不是仅根据订单数量判断程序是否正常。[查看运行检查](./operations-security.md)

<a id="q14"></a>

### Q14. 关闭程序、停止自动化或关闭浏览器，会自动取消所有挂单和仓位吗？

不会。软件停止或授权到期退出，并不代表交易平台上的订单、仓位或保护单自动撤销或结清；请在对应平台核对实际状态。参见 [运行维护](./operations-security.md) 与 [授权说明](./licensing.md)。

<a id="q15"></a>

### Q15. 启用 OKX BTC 合约自动化前，为什么要检查已有仓位与订单？

公开文档说明：启用实盘后，软件会**独占维护所连接账户的 `BTC-USDT-SWAP` 仓位及相关订单**；在核对或恢复时，可能取消不符合当前状态的订单或重建保护。因此应先检查当前仓位、普通订单、条件单和保护单，不要在同一账户、同一品种同时运行其他机器人或随意手工交易；可以考虑专用账户或子账户。[查看 OKX 首次使用检查](./quick-start.md#okx-btc-合约首次使用检查)

<a id="q16"></a>

### Q16. 断网、异常重启后，软件会自动恢复到完全正确的交易状态吗？

软件包含数据补齐、状态维护、异常重试和进程守护等机制，但**进程恢复不等于外部订单已自动消失，也不保证所有异常都能无人干预地解决**。恢复后仍须核对实时数据、订单、成交、仓位和保护状态。[查看运维与安全](./operations-security.md)

## 4. 市场数据、回测和收益理解

<a id="q17"></a>

### Q17. 为什么 Binance 行情与 Polymarket BTC 5m 最终结算结果可能不一致？

策略研究与信号判断所参考的交易所行情，不应直接视为 Polymarket 市场的最终结算依据。**结算规则和指定数据来源以对应 Polymarket 市场页面为准**；数据来源、时间边界与价格定义不同，都可能影响结果。不要只凭 Binance 某根 K 线的涨跌来推断结算。[查看公开架构](./architecture.md)

<a id="q18"></a>

### Q18. 为什么历史回测或 Paper 表现不错，Live 的结果仍可能不同？

真实下单会遇到实时盘口、成交价格、延迟、滑点、部分成交、交易费用、接口状态和运行中断等问题；历史研究还受到样本选取和验证方式的限制。因此应分别看待**历史回放、模拟运行和实盘记录**，不能互相替代。[查看研究报告与方法](../../reports/REPORTS.md)

<a id="q19"></a>

### Q19. 胜率高就代表实际盈利吗？

不代表。是否盈利还受到买入价格、赔率、费用、盈亏比、仓位规模、成交成功率和回撤路径等因素影响。方向预测正确不等于订单一定有正收益；也不能只凭短期胜率判断长期稳定性。

<a id="q20"></a>

### Q20. 报告中的 `+4 / -5 / 0` 标准化得分等于多少美元？

它是用于特定 Polymarket 历史回放比较的**统一计分口径**，不是美元、pUSD 实盘利润，也不能直接与 OKX 合约资金回放混算。不同策略参与频率不同，累计得分也不能单独作为优劣排名。[查看 Polymarket 回放报告](../../reports/REPORTS.md)

<a id="q21"></a>

### Q21. 历史报告可以证明机器人未来能够稳定赚钱吗？

不能。公开报告是对应日期和假设下的研究快照，并非第三方审计或实盘盈利证明。评估时应关注历史区间、参与数量、成本和成交假设、跨时期表现、回撤与验证限制；过去结果不保证未来结果。[查看报告中心](../../reports/REPORTS.md)

## 5. 凭证、账户安全和地区限制

<a id="q22"></a>

### Q22. 软件是否保管我的资金？私钥和 API Key 存放在哪里？

软件按公开文档以**自托管方式运行**：资金保留在用户自己的钱包和交易账户，交易签名在用户设备或自有服务器上完成；Polymarket 私钥与 Relayer API Key 由设备本地加密机制保存。这**并不表示设备、凭证或真实交易没有风险**，请自行保护主机与账户安全。[查看安全说明](./operations-security.md)

<a id="q23"></a>

### Q23. 只要设置了风控，是否就能避免亏损或自动交易故障？

不能。仓位限制、额度校验、数据健康检查和异常处理只能限制部分风险，无法消除市场方向错误、滑点、流动性不足、网络故障及第三方接口故障。启用实盘前应自行理解交易机制并设置可承受的风险边界。

<a id="q24"></a>

### Q24. 可以通过本软件绕过 Polymarket 或 OKX 的地区限制吗？

不可以。软件不用于绕过地理限制、账户限制、合规要求或当地法律。交易前应自行核实所处地区能否合法使用相关平台服务。

## 6. 故障反馈与更多资料

### Q25. 发现问题，提交反馈时应该提供什么？

建议提供**软件版本、操作系统、运行模式、出错时间、复现步骤、相关状态、已脱敏的日志和截图**。提交前删除或遮挡私钥、助记词、API Key、Token、密码、机器码及其他敏感信息；不要把敏感凭证发到公开 Issues。
